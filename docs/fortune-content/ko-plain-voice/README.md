# 한국어 운세 원고: 쉬운 말과 본문 분량

2026-09-16 사용자가 직접 제시한 “오늘은 행복한 하루가 될거야”, “잘 모르는 부분을 물어보기”, “실수 이후에 변명하기”를 기준으로 한 한국어 전체 교정 원고다. 이어 지정한 카테고리 전체 본문 4~5줄 목표를 함께 적용한다. [작성·검수 기준](CRITERIA.md)

현재 상태: 한국어 원고 작성·독립 검수 및 서비스 자산 연결 완료. 사용자의 후속 승인에 따라 개발 서버 PR·머지·배포·API 검증을 진행한다. 780개 원고를 작성자와 다른 담당자가 각각 읽었으며 교정된 전문도 다시 읽고 판정을 남겼다. 이전 배포 원고의 통과 기록을 새 원고의 승인으로 쓰지 않았다.

## 범위

- 총운·애정·금전·학업 및 직장·건강: 카드 78장 × 정역 2 × 5개 분야, 총 780개 원고.
- 총운의 총평·해볼 것·조심할 것: 각 156개, 총 468개 필드. 본문 780개 안에 포함된 별도 필드 수다.
- 총평은 쉬운 한 문장, 행동은 바로 알아듣는 짧은 행동구. 본문은 분야 전체 약 110~140자를 참고 범위로 삼아 4~5줄 정도의 읽을거리를 남긴다.
- 애정은 솔로·연애 중·이별 후의 세 단락, 학업과 직장은 두 단락을 유지한다. 다른 분야도 기존 단락 배열을 유지한다.

줄 수는 실제 화면 폭·글자 크기·단락 표시 방식에 따라 달라진다. 현재 모바일 소스의 기본 본문 크기 15px와 좌우 여백 24px를 참고했으며 앱을 실행해 렌더링을 검증한 결과는 아니다. 문장 수를 화면 줄 수라고 표시하거나 텍스트를 자르지 않는다.

## 실제 분량과 검수 결과

글자 수는 각 분야의 본문 단락을 공백 하나로 이어 계산한다. 총평·해볼 것·조심할 것은 제외한다.

| 분야 | 원고 수 | 본문 글자 수 중앙값 | 전체 범위 | 단락 수 |
| --- | ---: | ---: | ---: | ---: |
| 총운 | 156 | 133자 | 94~146자 | 2 |
| 애정 | 156 | 141자 | 130~152자 | 3 |
| 금전 | 156 | 123자 | 110~134자 | 1~2 |
| 학업·직장 | 156 | 131자 | 109~141자 | 2 |
| 건강 | 156 | 124자 | 112~132자 | 1~2 |

4~5줄은 편집 목표다. 특히 세 단락으로 나누는 애정은 화면에서 더 길어질 수 있다. 태양 역방향 총운은 반복되는 설명을 덜어 94자로 남겼고, 펜타클 6 역방향 애정은 행동 주체와 상대의 뜻을 분명히 말하기 위해 152자를 유지했다. 길이를 채우려고 새 상황을 덧붙이거나 뜻이 빠지도록 줄이지 않았다.

본문 780개를 모두 교정했다. 총평은 152개를 바꾸고 뜻이 쉽고 분명한 4개는 유지했다. 해볼 것·조심할 것은 각각 156개 모두 교정했다.

| 분야 | 작성·자체 재독 | 독립 검수 | 최종 판정 |
| --- | --- | --- | --- |
| 총운 | ko_overall_writer | root | 156개 통과 |
| 애정 | ko_love_writer | ko_overall_writer | 156개 통과 |
| 금전 | card_major_writer | ko_overall_writer | 156개 통과 |
| 학업·직장 | ko_love_writer | card_major_writer | 156개 통과 |
| 건강 | card_major_writer | root | 156개 통과 |

root는 태양 정방향·펜타클 3 역방향·탑 정방향의 다섯 분야를 합쳐 다시 읽었다. 이 15개는 이미 전수 검수한 780개 중 일부이며 추가 원고 수로 세지 않는다. 작성·독립 검수 모두 에이전트 검수이고 사용자 승인이나 사람의 감수를 뜻하지 않는다.

정적 검증 오류는 0개다. 참고 표시 116개는 글자 수 범위 밖 112개와 짧은 행동구 중복 4종이다. 전수 독해에서 분량을 함께 확인했으며, 비슷한 카드 뜻에 어울리는 아래의 쉬운 행동구는 억지로 다른 말로 바꾸지 않았다.

- 잘된 일 기뻐하기: 2개
- 잘 모르는 부분 물어보기: 3개
- 도와준 사람에게 고맙다고 말하기: 2개
- 서로 다른 말이 사실인지 확인하기: 2개

## 원고와 읽기 자료

- `overall.json`, `love.json`, `money.json`, `work.json`, `energy.json`: 새 한국어 원고. 읽기 키와 API에 쓰이는 필드·단락 구조를 유지한다.
- `*.author-review.json`: 작성자가 실제로 다시 읽은 내용과 해시. 자체 검토다.
- `*.independent-review.json`: 다른 담당자가 실제로 읽은 판정과 해시. 원고가 바뀌면 해당 판정도 다시 받아야 한다.
- `root-combination-review.json`: 같은 카드 한 장의 다섯 분야를 함께 읽은 최종 판정과 해당 전문의 해시.
- `generated/`: 원고에서 그대로 만든 분야별 전문, 총평·행동 전체 비교, 같은 카드 한 장의 전체 예시, 정적 검증 결과.

[전체 예시 3세트](generated/examples.md) · [총평·행동 468개 전후 비교](generated/short-comparison.md) · [총운 전문](generated/overall.md) · [애정 전문](generated/love.md) · [금전 전문](generated/money.md) · [학업·직장 전문](generated/work.md) · [건강 전문](generated/energy.md)

기존 카드 키워드·정역 의미·출처는 `../ko-rewrite/*.briefs.json`에서 확인한다. 예전 작가가 추가한 미시적인 상황과 작성 조건까지 카드의 고유한 뜻으로 취급하지 않는다. 새 원고의 말투·분량 판단은 이 폴더의 기준을 적용한다.

## 확인 방법

```sh
python3 docs/fortune-content/ko-plain-voice/build_review.py
python3 docs/fortune-content/ko-plain-voice/build_review.py --check
```

이 도구는 원고 누락·키·단락·기록된 실제 읽기 해시·검수자 분리를 검사한다. 길이와 중복은 참고 대상으로 표시한다. 자동 검사 성공을 한국어 품질이나 사용자 승인으로 표현하지 않는다.

## 반영 상태

`fortune-copy.v8-localized.3`의 한국어 원고로 연결했다. 생성기는 `ko-rewrite`와 `localization`의 기존 v8-localized.2 원고·검수 이력을 먼저 검증한 뒤 이 폴더의 한국어 작성자·독립 검수와 전문 해시를 확인해 한국어만 교체한다. 기존 검수 해시를 새 한국어 해시로 덮어쓰지 않는다. 영어·일본어는 기존 원문을 유지하며 새 한국어와 다시 현지화 등가 검수를 마쳤다고 표시하지 않는다.

일반 추첨의 780개 원고와 첫 방문 6세트에 같은 한국어를 연결하고, 세 언어 자산의 카탈로그 버전·출처 해시·manifest·전체 문서를 함께 생성한다. 첫 방문 세트의 ID·순서·카드 구성은 유지한다. 점수·점성술·카드 다섯 장 추첨·정역방향·사용자 간 멱등성은 바꾸지 않는다.

이미 저장된 당일 결과는 버전과 문구·해금 상태를 유지한다. 배포 후 새로 생성하는 운세부터 새 문구가 적용된다. 오늘 결과를 지우거나 문구 변경을 이유로 다시 추첨하지 않는다. 생년월일 변경에 따른 기존 재계산 동작도 유지한다. 잠금 상태의 `overall.flow` 공개와 `categories` 잠금, 공개 스키마는 그대로다.

DB 마이그레이션·환경변수·infra 변경은 없다. 개발 배포는 PR CI 통과 후 dev를 머지해 기존 GitHub Actions로 진행한다. 문제가 생기면 이전 dev `bfd7a0b2232083fe43b01a97307ba50da50a337c` 이미지를 배포할 수 있으며, 기존/새 버전의 당일 snapshot은 삭제하지 않는다. 운영 반영은 이번 범위에 없다.

검증은 원고·자산·문서의 정적 검사, PR CI의 전체 테스트, 개발 API의 배포 전후 비교로 나눈다. API에서는 전용 검증 계정으로 한·영·일 잠금/해금, 일반/첫 방문, 기존 당일 결과 보존, 새 원고 일치, 사용자 간 동일 결과, 생년월일 A→B→A와 해금 보존을 확인하고 검증 계정을 정리한다. 실행 결과는 PR에 기록한다. 로컬 앱·Docker·DB·pytest와 개인 AWS 계정은 사용하지 않는다.

작업 기준은 dev `bfd7a0b2232083fe43b01a97307ba50da50a337c`다. 별도 worktree의 `copy/fortune-ko-plain-voice`에서 작업하며 다른 대화·프론트 작업과 섞지 않는다.
