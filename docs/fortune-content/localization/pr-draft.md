# 개발 PR 설명과 검증·배포 조건

제목: 운세 카드별 세 언어 문구와 단락 연결 개선

## 설명 초안

기존 운세 문구를 사용자 승인 한국어 원고와 그 의미를 보존한 영어·일본어로 교체한다. 각 언어에 카드 78종 정역 × 5분야의 780개 본문과 총운 총평·해볼 것·조심할 것 468개를 제공한다. 애정은 솔로·연애 중·이별 후, 학업·직장은 상황이 바뀌는 곳에서 단락을 구분한다.

정본·작성자 재독·별도 독해 검수의 현행 원고가 일치해야 세 언어 실행 자산을 생성한다. 첫 방문 6세트는 ID와 카드 조합을 유지하고 같은 카드의 새 원고로 동기화한다. 점수·점성술·카드 추첨·광고 권한·기존 당일 결과는 유지한다. 추가 DB 마이그레이션과 환경변수는 없다.

공개 schema 3과 필드명은 유지하며 새 단락과 이전 snapshot을 함께 읽도록 배열 개수 검증을 확장한다. 모바일 빈 줄 표시와 건강 분야 제목(`건강 / Health / 健康`) 변경은 별도 패치로 첨부했고 클라이언트 작업 폴더에는 적용하지 않았다. 서버만 배포하면 기존 모바일의 `활력 / Energy / 活力` 제목과 문단 연결 방식은 그대로다.

## 제출 전 확인 상태

세 언어 원고 연결과 영어·일본어 별도 전수 독해 검수를 완료했다. 각 언어 본문 780개·짧은 문구 468개의 최종본을 확인했고 미해결 지적은 0개다. 독해 기록과 정적 검사 결과는 [README](README.md), [review.json](review.json), [validation.json](validation.json)에 구분했다.

한국어·현지화 검수 기록 및 예시 일치, 서버 자산 6개·대조 문서 6개 재생성 일치, 세 언어 편집 자산, 변경 Python 파일 Ruff, OpenAPI 계약·번들 검사가 통과했다. 로컬 앱·pytest·DB·Flutter 검증은 실행하지 않았다. CI와 새 빌드의 개발 API 검증은 PR·배포 후 수행해야 한다.

## 배포와 복구 조건

이번 대상은 `dev`뿐이다. 현재 `deploy-dev.yml`은 정확히 1대의 개발 서버를 중단 배포한 뒤 공개 health의 전체 SHA를 확인한다. 운세 변경만 별도 브랜치에서 제출하고, 병행 중인 대화 작업의 파일·커밋을 포함하지 않는다.

새 결과는 총운 2단락, 애정 3단락을 저장하므로 `flow=3/text=2`만 받는 기존 서버와 동시에 서비스하면 구 서버의 응답 검증이 실패할 수 있다. 다음 중 실제 배포 환경에서 검증한 방식으로 전환해야 한다.

1. 먼저 모든 서버를 배열 개수만 확장한 기존 문구 호환 빌드로 교체하고, 그 뒤 새 문구 빌드를 배포한다. `rollback-v6-reader-compat.patch`는 기준 `6ef287f5`에 적용할 해당 3개 스키마 파일의 패치다. 이 파일을 만들어 두는 것만으로 사전 배포가 된 것은 아니다.
2. 사전 호환 빌드를 배포하지 않는다면 운세 결과를 읽거나 생성하는 요청을 중지한 상태에서 모든 서버를 새 빌드로 바꾸고 구 서버가 응답하지 않는 것을 확인한 뒤 재개한다. 이 작업에서는 운영 인프라에 접속하거나 배포 설정을 변경하지 않았다.

새 결과 저장 후 원본 `6ef287f5` 이미지로 바로 복귀하지 않는다. 이전 문구를 다시 생성해야 한다면 그 기준 코드에 위 호환 패치를 적용한 빌드를 사용한다. 이미 저장된 v8 결과는 그대로 읽으며, 다음 신규 생성은 해당 이전 빌드의 v6 원고를 사용한다. 새 카탈로그 코드에 옛 JSON만 덮어쓰는 방식은 버전·단락 검증 때문에 실패하므로 복구 방법이 아니다. DB 결과를 삭제해 복구하지 않는다.

## PR 이후 검증할 항목

- 기존 CI: Ruff, OpenAPI 계약, 문구 생성 일치, 편집 자산 검사, 관련 회귀 검사 및 기존 전체 검사
- 새 빌드의 카탈로그 시작과 한·영·일 결과 생성, 세 언어 카드·조건 대응, 내부 카드 미노출
- 첫 방문 6세트 정본 일치와 점수 유지, 일반 결과의 동일 입력 재조회·동시 요청 멱등성
- 기존 당일 v6 저장본과 해금 상태 보존, 다음 날짜의 새 원고 적용, 프로필 변경 후 재계산
- 호환 빌드의 v8 저장본 읽기와 v6 신규 생성, 실제 전환 중 구 비호환 서버 잔존 여부
- 모바일 표시 패치 적용·지역화 코드 재생성 후 세 언어 건강 제목·긴 본문·단락·글자 확대 표시. 기존 저장본 표시 변화도 확인

후속 사용자 승인에 따라 dev PR·머지·개발 배포·검증까지 진행한다. 실제 CI 실행과 배포 전후 검증 결과는 제출한 PR에 기록한다. main PR·운영 배포·모바일 변경 적용은 이번 범위에 없다.
