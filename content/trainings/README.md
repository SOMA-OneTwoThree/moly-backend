# 승인된 트레이닝 원고

2026-10-21 사용자 제공 원고와 승인 구성: 긍정 회로 / 자기 수용, 각각30단계.

- `arrangement.json`: 2026-10-27 이전 원고의 단계·출처 번호·편집 기록. 문구의 기준은 아래 과정 원고이며, 이 파일은 출처(provenance) 기록으로만 남긴다. 무디 3.15.2 실제 서버 응답에서 확인한 답 방식·일기·문장 지우기 위치를 따른다. 무디의 숨겨진 채점 규칙을 복원했다는 뜻은 아니다.
- `positive.json`, `acceptance.json`, `refusal.json`: 과정별 ko/en/ja 원고. 단계마다 보기·보기별 힌트·해설·서버 전용 채점 기준(`grading`)을 담는다. 채점 기준과 예시는 화면에 전송하지 않는다. 긍정 회로·자기 수용의 예시(`grading.example`)는 회귀 평가에만 쓰고 AI 채점 프롬프트에는 보내지 않는다. 상황에 맞는 긍정적/자기수용적 방향 하나면 충분하며 상세 해설이나 특정 문구를 요구하지 않는다(2026-10-22 완화 기준 유지).
- `grading-eval.json`: 모범답안과 독립적으로 쓴 26단계의 짧은 자연어 답·명백한 반례·사용자 QA 재현. `grading-eval-holdout.json`: 기준 작성 후 추가한 별도 표현으로 검증한다. `scripts.evaluate_training_grading --suite all|natural|heldout`으로 실제 모델 평가를 명시 실행한다.
- `legacy-catalog.json`: 옛 원고. 새 카탈로그에서 archived 처리하므로 목록에는 안 나오고, 옛 id의 진행/답 조회는 유지한다.
- `build_catalog.py`: 세 과정 원고와 `legacy-catalog.json`을 합쳐 실행용 `app/resources/trainings/catalog.json` 생성. 새 문제는 새 id로 분리했다. 2026-10-22 승인으로 활성 두 과정 보상은 30/60/150. 기존 지급 이력은 재지급하지 않는다.

```sh
uv run python content/trainings/build_catalog.py
uv run python content/trainings/build_catalog.py --check
uv run pytest -q tests/test_training_catalog.py tests/test_training_grading.py
```

원고별 객관식/주관식: 긍정 회로13/17, 자기수용21/9. 2026-10-23 팀 QA에 따라 두 주제 모두 30개 서로 다른 원문 상황을 사용한다.
2026-10-22 사용자 QA에 따라 16개 단계 해설에서 보기 번호·부가 평가·반복 설명을 제거했다. ko/en/ja 원고에 함께 반영했다.
자기수용18은 원본처럼 빈칸 없는 일반 객관식이다. 앱은 통과/재열람에서 선택한 답을 별도 표시한다.

무디의 `review_type` 값은5/15/30에 있지만 이를 자동 답변 모아보기로 단정하지 않는다.
앱은 보상 후 다음 단계/완료로 진행한다. 2026-10-22 요청으로 하단 기록 모아보기 진입은 제거하며, 완료한 단계의 답 재열람은 유지한다.

## 출시 순서

1. `db/changes/explore_training.sql`이 이미 적용된 환경에서 `db/changes/training_submissions.sql`을 검토·적용한다. 기존테이블 초기화나 계정 데이터 전환은 없다.
2. DB 계약을 검증한 뒤 이 백엔드와 앱을 배포한다. 빈칸 없는 선택형을 제공하므로 해당 앱 수정도 함께 필요하다.
3. 동시 제출의503 `TRAINING_SUBMISSION_PENDING`은 같은 요청 id로 재시도한다. 서버 중단 시30초 선점 만료 후 다시 채점한다. 결과가 있으면 최초 판정을 재사용한다.
4. 롤백은 서버/앱 버전을 되돌리되 새 테이블·저장 답을 삭제하지 않는다. 구버전 서버에는 이번 멱등 오류 수정이 없으므로 롤백 시 해당 보장이 사라진다.

2026-10-21 dev DB에 `training_submissions.sql`을 guarded dry-run → SHA-256 확인 → commit 순서로 적용했다. `uv run python -m db.verify --env dev`의 전체 계약 검증 통과. 운영 DB와 배포 서버는 변경하지 않았다. 로컬 PostgreSQL17 통합 검사에 이어 dev DB·실제 AI·iOS 시뮬레이터로 검증한다.
실제 AI 평가는 `uv run python -m scripts.evaluate_training_grading --output /tmp/training-grading.json`으로 명시 실행한다. 합성 답만 보내며 계정·DB 기록은 사용하지 않는다. 모델 실패를 평가 통과로 세지 않는다.

## 문제 그림 (2026-10-21)

과정 원고의 단계별 `icon_key`는 앱에 이미 포함된 Fluent Emoji 3D 에셋 키다. 두 과정 60개 모두 상황에 맞춰 지정했다. 생성 원고와 공개 API로 전달하며 언어에 따라 바뀌지 않는다. 예전 과정의 누락 키는 그림 없음으로 처리한다. 무디 원본 그림을 복사하지 않는다.

## 2026-10-23 팀 QA: 반복 제거

활성 과정은 `positive-circuit-v2`, `self-acceptance-v2`이다. 긍정 회로 2·4, 자기 수용 3·5·7·9·11·13·15·17·19단계를 미사용 노션 원문으로 교체했다. 유형 순서와 보상 위치는 유지했다. 각 단계의 출처는 arrangement의 provenance에 기록했다.

이전 v1 원고는 그대로 보존하며 기존 답은 이전 id로만 조회한다. v2 진행과 보상은 별도 과정으로 시작한다. DB의 기존 답·보상 행을 수정하지 않는다. 과거 QA 재현 평가도 해당 v1 문제에 연결한다.

노션 확인: 긍정 회로 `4007d39cd13a80bd8027e27ed7e01742`, 자기 수용 `4007d39cd13a80a98743e2d77112cd4e`. 일기/지우기형으로 편집한 경우 provenance에 표시했다.

## 2026-10-24 거절 연습

`refusal.json`은 사용자 제공 30단계 원고와 승인된 편집을 담는다. `refusal-practice-v1`로 기존 두 과정과 기록을 분리하며 객관식 16개, 글쓰기 14개다. 7→8, 14→15, 19→20→21은 의도적으로 같은 상황을 이어간다.

- 거짓 핑계를 요구하지 않으며, 상대의 감정이나 관계를 단정하지 않는다.
- 글쓰기는 상황에 맞는 짧은 거절도 허용한다. 감사·사과·이유·대안을 필수로 요구하지 않는다. 다만 9단계는 생각할 시간 확보, 21단계는 다른 방법 안내가 미션이다.
- 글쓰기 해설은 성공한 응답에만 포함한다. 예시 답안은 원고에 저장하거나 사용자에게 보내지 않는다. 별도 평가 파일의 합성 답변은 검증 전용이다.
- 2026-10-24 요청으로 모든 과정의 보상을 5/15/30단계 각각30/60/150개(총240개)로 통일했다. 기존 지급 이력과 잔액은 변경하지 않는다.
- `grading.topic=refusal`은 서버 전용 분기다. 기존 긍정 회로/자기 수용 채점 프롬프트는 유지한다.
- 생성은 `build_catalog.py`를 사용한다. 신규 DB 테이블이나 데이터 초기화는 필요 없다. 클라이언트의 주제별 최초 안내와 함께 배포한다.

## 2026-10-27 문체 통일

세 과정 90단계의 한국어 문장을 하나의 문체로 다시 썼다(사용자 검토·승인). 단계 번호·형식·줄 수·화자·빈칸 위치·보기 id·정답 위치는 그대로라 저장된 답과 진행 기록은 영향이 없다.

- 객관식 세 보기를 정답 / 그럴듯한 함정 / 명확한 오답으로 설계하고, 틀린 보기마다 그 보기에 맞는 힌트를 둔다. 문장 지우기형의 남길 문장은 기존 힌트를 유지한다.
- 미션은 정답을 흘리지 않는 질문으로, 해설은 모든 단계에 1~2문장으로 맞췄다. 긍정 회로·자기 수용 글쓰기에도 해설과 다시 도전 힌트(`grading.retry_hint`)를 추가했다.
- 숫자 표기(단위가 붙는 수량은 아라비아 숫자), 대화형 해요체·일기형 반말을 통일했다. 영어·일본어는 새 한국어 기준으로 다시 번역했다.
- 채점 기준은 2026-10-22 완화 방향을 유지한 채 새 미션에 맞게 옮겼다. 거절 연습은 예시 답을 저장하지 않는다.
- 이전 단계별 원문·번역·기준(`ko-source.json`, `translations.tsv`, `rubrics.tsv`)은 과정 원고로 대체되어 삭제했다. git 기록에서 볼 수 있다.

## 2026-10-28 영어·일본어 다듬기

세 과정 원고의 영어·일본어판을 다듬었다. 단계·줄·빈칸·보기 id·정답 위치는 그대로라 저장된 답과 진행 기록은 영향이 없다.

- 일본어: 혼잣말 보기의 1인칭은 「自分」, 상대에게 하는 말은 「私」. 안내문은 사용자를 「あなた」로 부르지 않고 です・ます체로 통일. 「あんた」를 없애고, '서운하다'를 문맥에 맞게 옮겼다.
- 영어: 보기를 한국어 길이에 가깝게 줄이고, 일기 빈칸(긍정 2)이 앞뒤 지문과 문법에 맞게 이어지도록 고쳤다. 선배는 senior coworker.
- 영어·일본어판의 한국 소재(원화, 성수동, 제주·우도, 김치찌개 등)를 현지 일상에 맞게 바꿨다. 한국어판은 그대로다.
- 한국어 포함: 자기 수용 5·11·17·22(지우기) 오답 힌트를 보기마다 다른 이유로 다시 썼고, 거절 9의 고정 이름(하늘님)을 없앴다.
