# GPT-6 모델 전환 구현·검증

2026-09-23. **운영 미반영. 개발 배포 검증과 운영 준비를 분리한다.**

이 문서는 조사 당시의 후보 추천을 실제 구현 범위로 구체화한다. 구독 정책 변경과 함께 준비하되 모델별 사용자 등급이나 새 과금 체계를 만들지 않는다. 코드 작업은 main 기반 `feat/subscription-policy-safety`, 인프라는 별도 `feat/gpt6-model-routing` 작업 폴더에 있다. 현재 main/dev 차이를 한 번에 병합하지 않는다.

## 역할과 활성화

| 역할 | 이전 | 새 기본값 |
|---|---|---|
| 일반·주제·운세 대화 | GPT-5.6 Luna | GPT-6 Luna |
| 요약·검수·번역·기억 통합·규칙 정리 | GPT-5.6 Luna | GPT-6 Luna |
| 개인 일기 작성 | GPT-5.6 Terra | GPT-6 Sol |
| 기억 추출 | GPT-4.1 mini 고정 버전 | 유지 |
| 임베딩 | text-embedding-3-small | 유지 |

신규 이미지 배포가 모델 전환 시점이다. 구독의 전환 시각 T와 모델 전환은 별개이며, T까지 모델을 바꾸지 않아야 한다면 이미지 배포도 그에 맞춘다. 개발의 실제 전환은 배포 후 /health 버전과 호출 원장으로 확인한다. 운영 전환은 별도 승인 후 진행한다.

기본 모델을 코드에 지정했으므로 전환에 새 SSM 파라미터를 만들 필요는 없다. `MODEL_CHAT`, `MODEL_DIARY`, `MODEL_UTILITY` 환경변수는 기존 지원 방식을 유지한다. infra는 `/moly/{dev|prod}/model-chat`, `model-diary`, `model-utility`가 **있을 때만** 환경변수로 전달하도록 준비했다. 미설정이면 이미지 기본값을 사용하며, 빈 값·공백·개행이 포함된 모델 ID는 실행 중인 env 파일 교체 전에 거절한다. API·consumer·batch가 동일한 env를 사용한다.

## 호환성과 사용자 차감

- Chat Completions를 유지한다. 도구 경로의 `reasoning_effort=none`을 보존한다. GPT-6 Luna/Sol 도구 호출의 공식 호환 조건이다.
- 개인 일기 생성은 기존과 같이 모델 기본 추론 설정을 유지한다. 일기 프롬프트와 후처리, 공개 시각, 멱등 키는 변경하지 않는다.
- 짧은 utility 출력은 추론을 명시적으로 끈다. 일기 검수, 번역, 문자 복원, 문맥 요약, 규칙 정리가 해당한다. 이미 none을 지정했던 기억 분류/통합은 그대로다.
- 실제 개발 검증 중 GPT-6 Luna의 16토큰 검수에서 400 출력 상한 오류 2건을 확인했다. 검수는 none + 64토큰으로 수정했다. 본문 길이·사용자 대화 한도와 무관하다.
- 사용자의 차감 공식과 캐시 버킷 분류는 유지한다. 모델별 실사용 토큰은 달라질 수 있지만 가격 인하를 이유로 차감 가중치·누적 사용량을 변경하지 않는다. 언어별 무료 4/5/6만·가입 체험 및 구독 30/40/55만(영어/한국어/일본어)과 T는 별도 구독 정책 구현을 따른다.

## 회사 원가

원가 계산과 사용자 한도 차감을 구분한다. OpenAI 응답에 `prompt_tokens_details.cache_write_tokens`가 있으면 명시적 0도 그대로 원가에 반영한다. 입력은 일반·읽기·쓰기의 배타적 세 버킷이며 이중 계산하지 않는다. 쓰기 사용량이 빠졌으면 GPT-5.6/6만 기존 보수적 추정을 유지하고 `cache_write_estimated=true`를 남긴다. GPT-4.1 mini에는 임의의 쓰기 프리미엄을 붙이지 않는다.

| 모델 | 입력 | 캐시 읽기 | 캐시 쓰기 | 출력 |
|---|---:|---:|---:|---:|
| GPT-5.6 Luna | 0.20 | 0.02 | 0.25 | 1.20 |
| GPT-5.6 Terra | 2.00 | 0.20 | 2.50 | 12.00 |
| GPT-6 Luna | 0.10 | 0.01 | 0.125 | 0.50 |
| GPT-6 Sol | 2.00 | 0.20 | 2.50 | 10.00 |

USD/100만 토큰, Standard, 입력 272K 이하. 272K 초과 요청 전체에는 입력·캐시 2배/출력 1.5배를 적용한다. 다른 처리 등급·지역 가산·청구 할인까지 대사했다는 뜻은 아니다.

`db/changes/gpt6_price_catalog.sql`은 새 catalog_version=20260923의 4행만 추가한다. 최초 적용 시각부터 효력이 생기며 재실행은 같은 행을 유지한다. 동일 버전에 다른 금액이 있으면 실패한다. 기존 가격·과거 원장을 덮어쓰지 않고 새 테이블/컬럼도 만들지 않는다. seed는 신규 DB 초기화에만 쓴다. 운영 전환에 seed 전체를 실행하면 안 된다.

개발 평가 도구도 캐시·단가를 반영하고, 미등록 모델의 원가를 0원으로 표시하던 부분을 null로 수정했다. 기본 비교군은 이전/새 Luna와 Terra/Sol이다.

## 배포 전 사전 검증 결과

- 백엔드 전체 단위 테스트: 2,513개 통과. 이후 64토큰 보호 테스트를 추가하고 관련 73개 재검증 통과. lint, OpenAPI 계약, diff 검사 통과.
- 실 OpenAI SDK 응답 타입으로 cache write 미보고/명시적 0/양수, 이전 모델 복구, tool/text 원가 동등성, 사용자 차감 불변, 긴 입력 가격 경계를 검증했다.
- 개발 PostgreSQL에서 실제 가격 SQL을 두 번 실행해 멱등성·기존 행 보존·충돌 거부를 확인했다. 트랜잭션 롤백 후 전체 단가 테이블이 원래와 같음을 확인했다. 지속적인 dev/prod DB 변경 없음.
- 인프라 배포 스크립트는 AWS/Docker/DB 실행 대신 명령 대역으로 검증했다. 10개 테스트 통과, 선택 비교 테스트 1개 건너뜀. dev/prod 모델 전달, 잘못된 값일 때 기존 env 보존, 미설정 시 기존 동작을 확인했다. 로컬 Docker/DB는 기동하지 않았다.
- **기존 개발 API에서 실제 모델 호출 34회**: 접근 확인 2회, 다국어 비교 26회, 검수 상한 수정 재확인 6회. 사용자 실제 대화가 아닌 합성 문장만 사용했다. 원래의 16토큰 검수에서 확인한 실패 2건은 아래 별도 기록을 유지한다.
- 한·영·일 대화, 개인 일기 포맷, JSON 구조, 개인정보 경계 응답을 읽고 검토했다. 새 모델 표본은 응답 언어와 지정된 형식을 지켰다. 일기는 제시된 발표/안도/휴식 맥락을 유지했다. 이 소규모 표본이 장기적인 문체 선호·안전성을 보장하지는 않는다.
- 검수 상한을 64로 바꿔 새 Luna를 언어별 2회씩 호출한 6회는 모두 OK였다. 기존 dev 평가 API는 reasoning 값을 지정할 수 없으므로 이 실측은 **기본 추론 상태에서 상한을 늘린 확인**이다. none 설정은 구현·회귀 테스트로 확인했다.

실측 지연(언어별 각 1회, 기본 추론, 통계적 성능 비교 아님):

| 용도 | 이전 | 새 모델 |
|---|---|---|
| 대화 | Luna 1.61–2.50초 | Luna 1.46–2.32초 |
| 일기 | Terra 2.62–3.11초 | Sol 4.85–6.39초 |

Sol 일기는 이 표본에서 더 느렸고 추론 포함 출력 토큰도 늘었다. 단가 인하를 실비 절감 확정으로 표현하지 않는다. 지연은 백그라운드 일기 생성 구간이며 대화 모델을 Sol로 바꾸지는 않았다.

### 사전 검증의 한계와 배포 검증

현재 dev의 `/dev/chat-eval`에는 도구 스키마와 임의 system 역할을 넘길 수 없다. 대화는 실제 페르소나를 사용했지만, 일기·utility는 해당 지시문을 user 메시지에 넣은 호환성 검증이다. **새 코드가 배포된 실제 도구 왕복·일기 배치·원가 원장 적재의 종단 검증은 배포 후 남아 있다.** 단위 테스트나 위 호출을 이 배포 검증 완료로 보고하지 않는다. 운영 API/계정/원가/파라미터에는 변경하지 않았다.

합성 응답 원문과 실패/재검증 이력: [실측 보고서](validation/gpt6-dev-2026-09-23.json)

## 이후 반영 순서와 복구

1. 다른 작업과 분리해 이 변경만 최신 dev에 통합한다. 구독의 선행 DB 변경과 합쳐 한 번에 적용할지는 별도 통합 단위로 관리한다.
2. 개발 DB에 가격 SQL을 적용한다. 4개 모델의 최신 유효 단가·신규 테이블/컬럼 없음·기존 원장 보존을 확인한다.
3. 개발 API·consumer·batch에 같은 이미지를 배포하고, 실제 모델/원가 catalog_version, 한·영·일 대화, 도구 왕복, 일기 생성/검수/번역, 재요청 시 중복 차감·생성 없음을 확인한다.
4. 운영은 승인 후에만 준비한다. 운영 DB에는 구독 함수 SQL과 모델 가격 SQL을 구분해 선적용하고 두 서비스/모델 코드의 배포 범위를 확정한다. 전체 dev→main 병합은 하지 않는다. 모델 코드만이라면 새 SSM 값 입력은 필수가 아니다.
5. 모델 회귀는 직전 이미지로 복구한다. infra 옵션이 반영돼 있으면 MODEL_CHAT/UTILITY=`gpt-5.6-luna`, MODEL_DIARY=`gpt-5.6-terra`로 역할별 복구 후 API와 워커를 함께 재기동할 수도 있다. 새 가격 행과 원장은 남긴다. 가격 행 삭제·사용량 초기화·결제/체험 재부여로 복구하지 않는다.
