# BeCappy 백엔드 문서 안내

`docs/`에는 현재 코드의 기술 계약만 둔다. 구현 과정의 계획서, 시점성 상태 보고서, 발표·사업·광고 자료는
기술 계약과 섞지 않는다.

## 기준 문서

| 문서 | 역할 |
|---|---|
| `API_SPEC.md` | 모바일 앱과 백엔드가 주고받는 공개 API 설명 |
| `ARCHITECTURE.md` | 백엔드 전체 구조·핵심 흐름·운영 원칙 |
| `ARCHITECTURE-capi.md` | 대화·장기 기억·도구·관계·비동기 작업 상세 |
| `ERD.md` | 테이블·제약·권한·데이터 수명 주기 |
| `DAILY-FORTUNE.md` | 오늘의 운세 입력·계산·문구·DB·API·광고·배포 상세 |

HTTP 계약의 기계 판독 원본은 `openapi/openapi.yaml`과 분할 YAML이며, DB 구조의 원본은
`app/models/`와 `db/schema.sql`이다. 문서가 코드와 다르면 코드 원본을 확인한 뒤 문서를 함께 수정한다.

## 정리 원칙

- 새 기능의 최종 설계는 전체 구조 또는 해당 도메인 상세 문서에 합친다.
- 구현 중 임시 계획과 실험 로그를 별도 문서로 계속 쌓지 않는다.
- 완료된 마이그레이션의 실행 이력은 `db/migrations/`에 남기고 중복 체크리스트는 제거한다.
- 생성 파일, 운영 데이터 덤프, 비밀값과 `.env`는 문서 디렉터리에 두지 않는다.
- 시점성 운영 수치와 남은 작업은 이 디렉터리의 구조 문서에 누적하지 않는다.
