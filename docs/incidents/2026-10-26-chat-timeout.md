실패한 요청의 입력과 제공자 추적 ID가 없어, 당시 지연을 제공자 큐·네트워크·출력 생성 중
어느 것으로 확정할 수는 없다. 캐시 미적중도 다른 서버로 라우팅됐다는 증거가 아니다.
**확인한 원인은 앱의 첫 호출과 복구 호출이 모두 시간 예산을 소진한 것까지다.**

## 실제 런타임 반례와 채택하지 않은 변경

추가 18회는 실제 런타임/SDK에서 첫 도구 판단만 통제된 시간 초과로 만들고, 실제 제공자를
호출하는 대체 경로를 비교했다. 개발 기본 전체 예산 8초 중 첫 호출이 4초를 사용하도록 했으며,
대체 호출의 실제 남은 시간은 약 3.995초였다. 운영 전체 예산 10초와 동일한 전체 턴 재현은 아니지만,
문제의 대체 호출 예산 약 4초와 취소 동작을 직접 검증한다.

모델 3종 × 기존/후보 × 일본어 일반·설명/한국어 정정 = 18회.
기존 경로는 9/9 성공, 짧은 답변 후보는 8/9 성공했다. 후보의 실패 1건은 **운영 모델 gpt-6-luna**의
한국어 정정 사례로, 약 4초에 취소됐고 전체 턴은 8.006초였다. 나머지는 마감 안에 완료됐다.
이를 개선 효과로 주장할 수 없어 **짧은 답변 프롬프트 변경은 최종 PR에서 제외했다.**

총 150회 실제 응답 실험(48 + 84 + 18) 외에 두 모델로 답변 품질과 코드/증거를 교차 검토했다.
모델 판정도 검증 대상이다. 최초 코드 검토에는 주변 코드 미제공으로 잘못 추정한 출력 한도·재시도 지적이
있었고, 전체 흐름과 설치 SDK 테스트를 제공해 재검토했다. 품질 판정은 항목 누락·중복 및 합성 이력
오독이 있어 자동 합격률로 사용하지 않았다. 안전 사례에서 짧게만 답하도록 강제하는 위험도 검토했다.

## 최종 수정 범위와 계약

- 정상 첫 응답, 도구 결과 응답, 시간 초과 대체 응답, 기존 출력 잘림 복구 지시를 모두 유지한다.
- 모델, 출력 한도 1024, 전체 예산, 최대 재시도 수를 유지한다. 실패 시 세 번째 논리 호출은 없다.
- OpenAI 물리 호출마다 `X-Client-Request-Id`를 전송한다. 전송 직전과 종료 시 ID를 기록하고,
  응답이 있으면 제공자 `x-request-id`, 지연, 상태도 남긴다. 프롬프트·답변·사용자 ID·키는 새 로그에 넣지 않는다.
- `outcome=received`는 HTTP 응답 수신이며, 완결된 사용자 답변이라는 뜻은 아니다.
  추적 ID는 하나의 SDK 재시도 묶음 안에서 연결되며 전체 사용자 턴의 공통 ID는 아니다.
- 실패 호출 비용은 회사 원장에 남기되, 사용량을 받지 못한 시간 초과는 `unknown`이다.
  사용자에게는 성공해 발행한 응답만 기존 공식으로 차감한다. 중복 요청 재전송도 추가 차감하지 않는다.

추가 모델 호출이나 프롬프트 변경은 없다. 물리 호출당 시작/종료 메타데이터 로그가 추가되어 로그 비용은 소폭 늘 수 있다.
요금제·구독·사용자 차감 공식 변경은 없다. 실패한 제공자 호출이 회사 측에서 무료라는 뜻도 아니다.

제공자 추적 헤더 근거: [OpenAI API request IDs](https://developers.openai.com/api/reference/overview).
이 PR은 진단 보강과 회계 회귀 검증이다. 시간 초과 오류를 제거하는 수정이라고 주장하지 않는다.

## 검증 및 후속 확인

서비스 런타임 → 설치된 SDK → 가짜 HTTP → 채팅 발행 흐름으로 시간 초과/잘림 복구와
두 사용자 차감 플래그, 성공/실패 시 원장, 중복 요청, 취소, 세 번째 호출 방지, 기존 마감 준수를 검증한다.
실제 모델 호출과 DB 회계 검증은 분리하여 운영 사용자를 소비시키지 않는다.

배포 후에는 시간 초과율과 fallback 성공률을 정상 트래픽에서 비교하고, 새 ID로 실패 호출을
제공자 기록과 대조해야 한다. 실패 요청 미차감·성공 답변 1회 차감은 원장과 메시지를 함께 확인한다.
개인 대화 원문을 추가 로깅하는 방식은 사용하지 않는다. 이 PR 작성 시 운영 배포는 하지 않았다.

최종 검증: 전체 로컬 테스트 **3,423 passed / 191 skipped**, 전체 Ruff 통과.
191개는 외부 DB 등 별도 실행 조건이 필요한 테스트다. OpenAPI 계약 테스트는 전체 테스트에 포함된다.
최종 코드로 실제 모델 3종을 추가 호출해 모두 3.95초 안에 완료했고(3.175 / 1.771 / 1.741초),
전송된 client request ID와 시작/종료 로그가 일치하며 provider request ID도 기록됨을 확인했다.
따라서 실제 응답 호출은 총 153회다(모델 검토 호출 별도).
