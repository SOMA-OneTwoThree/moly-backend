# 한국어 전체 편집 및 점수대 차등화

2026-09-09. 상태: 한국어 1,000문단 작성·독립 전량 검수·수정본 재독·개발 DB 검증 완료. PR·서버 배포 전. 사용자 승인 예시는 [5세트 검토 기록](samples/2026-09-09-editorial-pilot.md), 점수대별 작성 계약은 [briefs.json](briefs.json)에 있다.

## 범위와 호환성

- 한국어 총평 200묶음(제목·본문·행동·주의)과 네 분야 각 200문단, 총 1,000문단을 문단 단위로 다시 작성한다. 영어·일본어는 변경하지 않는다.
- 점수 구간마다 20개 ID를 유지한다. 같은 구간의 긍정·부정 강도는 비슷하게 유지하되 상황과 제안이 다르게 읽혀야 한다. 다른 구간에서 첫 문장만 바꾼 같은 문단을 재사용하지 않는다.
- 본문은 약 5문장, 기존 API 전송 구간은 flow 3/text 2다. 완료한 문단을 전송용으로 나누며 서로 다른 원고에서 문장을 가져다 조합하지 않는다.
- 점수 함수·분포·선택 순서·DB 스키마·광고 공개 상태는 이번 편집으로 바꾸지 않는다. 이미 생성한 당일 snapshot은 유지되고 새 결과부터 새 한국어 자산을 사용한다.
- 묶음 버전은 `fortune-copy.v3-ko-editorial.1`이다. 한국어 자산은 이 버전을 사용하고 영어·일본어는 `fortune-copy.v3-independent.1`을 유지한다. 각 언어 버전을 별도로 검증한다.
- 기존의 언어 공통 선택 ID와 점수는 유지한다. 현재 영어·일본어를 새 한국어의 번역본이라고 표현하지 않는다. 번역·의미 정합성 검수는 사용자 지시대로 후속 작업이다.
- 행운색과 UI 버튼 명칭은 승인 예시의 일반적인 색 이름·기존 짧은 표현을 유지한다. 앱 렌더링과 점수 코드는 이전 구현을 그대로 사용한다.

## 작성과 판단 분리

총평, 애정·금전, 일·학업·활력의 세 작성 담당으로 나누었다. 작성자는 루트 20편마다 저장하며 독립 판단자는 실제 문단을 읽고 부자연스러운 구절·점수 강도·반복·분야 독립을 검토한다. 작성자 본인의 구조 검사와 독립 판단 결과를 구분해 기록한다.

판단 기준은 자연스러움, 즉시 이해, 운세 해석, 점수 적합, 분야 독립의 다섯 가지다. 각 4/5 이상을 목표로 하되 점수만으로 통과시키지 않는다. 문제 구절과 수정 근거를 남긴다. 문장 수·중복·금칙 표현 검사는 보조 수단이며 전량 통독이나 원어민 검수를 대신하지 않는다.

`무난`은 사용자 승인 예시에도 쓰인 일반어이므로 기존 일괄 금지 정규식에서 제외했다. 단어 자체가 아니라 해당 점수의 구체적인 해석 없이 모든 내용을 무난하다고 표현하는 경우를 문단 검수에서 판단한다. `~겠어`, `흐름이야` 등 기존 퇴역 말투 검사는 유지한다.

코드는 기존 개발 DB에 연결해 검증했으며 실행 중인 개발 API에 배포하지 않았다. 로컬 Docker·새 DB·운영 DB 작업은 하지 않았다. 점수와 선택 순서가 바뀌지 않았으므로 문구 강도 차이를 점수 분포 변경으로 설명하지 않는다. 실제 화면의 줄 수는 기기 폭과 글자 크기에 따라 달라진다.

## 인계와 제한

`judge-findings.json`에 73건의 정확한 route/variant, 인용, 수정 제안, 재검수 상태, 최종 파일 SHA-256을 보관했다. 작성자가 각자 `/tmp` 원고만 고쳤고 판단자가 제품 자산이나 DB를 변경하지 않았다. 한국어 모델 독립 검수이며 사람·원어민 전문가 인증이 아니다. 이후 root의 통합 과정에서 다시 바뀌는 문장은 해당 수정 범위를 별도로 확인해야 한다.
