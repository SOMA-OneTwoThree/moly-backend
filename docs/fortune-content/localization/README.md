# 일본어·영어 현지화와 서버 연결 준비

상태: 일본어·영어 집필, 별도 전수 독해 검수, 서버 자산 연결과 정적 검사 완료. 확정한 [한국어 정본](../ko-rewrite/README.md)의 본문을 유지했다. 후속 사용자 승인 범위는 운세 변경의 dev PR·머지·개발 배포·실제 검증까지이며 운영과 모바일 배포는 포함하지 않는다. CI와 배포 전후 API 검증 결과는 해당 PR에 기록한다.

[세 언어 예시 4세트](samples.md) · [총운 전문](../overall.md) · [애정](../category-love.md) · [금전](../category-money.md) · [학업·직장](../category-work.md) · [건강](../category-energy.md) · [첫 방문 6세트](../first-visit.md)

## 범위와 기준

| 대상 | 수량 | 담당 |
| --- | ---: | --- |
| 영어 | 780개 본문 + 총평·해볼 것·조심할 것 468개 | 영어 집필 에이전트 |
| 일본어 | 780개 본문 + 총평·해볼 것·조심할 것 468개 | 일본어 집필 에이전트 |
| 언어 품질·의미 비교 | 영어 root 전수 독해, 일본어 별도 검수자 전수 독해, root 초기·조합 검수·최종 통합 | 작성자 외 검수 담당 |
| 서버 연결 | 자산 생성·카탈로그·공개 계약·첫 방문·기존 문서·회귀 검사 준비 | 별도 구현 에이전트, root 검토 |

한국어의 [최신 집필 기준](../ko-rewrite/CRITERIA.md)과 [승인 예시](../ko-rewrite/approved-example.md)가 의미의 기준이다. 예전 스킬에 남아 있는 점수에 따른 문구 선택·단일 문단 규칙은 이번에 적용하지 않는다. 점수·점성술·카드 추첨·사용자 간 멱등성은 이번 작업에서 변경하지 않는다. 각 카드의 정·역방향 해석과 각 분야의 운 판단을 유지한다.

각 언어의 `overall/love/money/work/energy.json`은 한국어와 같은 reading key와 필드를 사용한다. `paragraphs`의 개수와 순서를 보존한다. 총운은 2단락, 애정은 솔로·연애 중·이별 후의 3단락, 학업·직장은 2단락, 금전·건강은 해당 한국어와 같은 1~2단락이다. 한 문장씩 줄바꿈하거나 본문 안에 상황별 소제목을 덧붙이지 않는다.

## 언어별 작성 원칙

### 공통

- 한국어 원고와 근거표의 운 판단, 확신의 정도, 조건, 행동을 빠짐없이 유지한다. 새로운 사건·개인 사정·관계 성별을 만들어 넣지 않는다.
- 결과를 먼저 말하고 같은 상황의 설명과 조언을 잇는다. 한국어 단어 순서와 어미를 직역하지 않는다.
- 총평은 본문을 읽지 않아도 이해되는 한 문장이다. `do`는 짧은 행동, `pause`는 조심할 행동 자체다. 조심할 행동을 부정 명령으로 바꿔 의미가 뒤집히지 않게 한다.
- 정방향을 모두 좋게, 역방향을 모두 나쁘게 만들지 않는다. 거절을 존중하는 조건, 재회의 상호 의사, 공부와 직장의 구분을 유지한다.
- 건강·재물 원고에 한국어에 없던 진단이나 확정 수익을 더하지 않는다. 카드 이름·정역·키워드·제작 설명은 사용자에게 표시할 본문에 넣지 않는다.
- 실제 현지 운세 본문을 열어 어법을 참고하되 문장을 복사하지 않는다. 이번에 읽은 범위·접근 실패·채택 범위를 작성자 기록에 남긴다. root가 추가로 확인한 현지 본문은 review.json의 source_reading에 구분한다.

### 일본어

친근하고 읽기 쉬운 です・ます체를 기본으로 한다. 한국어 반말을 だよ・してみて로 반복하지 않는다. 불필요한 あなた・自分, 어색한 명사 나열, 매 문장의 でしょう・かもしれません을 경계한다. 조사와 서술어의 결합을 확인한다. 。와 、를 사용하며 문장 사이에 불필요한 공백을 넣지 않는다. 솔로·교제 중·이별 후의 상황은 문장 안에서 자연스럽게 구분한다.

### 영어

일상적인 영어와 자연스러운 축약형을 사용한다. Today, You, It's a good day to로 문장을 기계적으로 시작하지 않는다. align·embrace·navigate 같은 추상적인 격려, 회사 보고서 말투, 운명에 관한 과장된 상투어로 내용을 대체하지 않는다. 빠진 주어와 목적어를 영어에 맞게 밝혀 한국어의 생략을 그대로 옮기지 않는다. 조언과 예측의 강도를 구별한다.

## 검수 절차

1. 전차·태양·탑·달·절제 정역의 다섯 분야를 언어별 50개 먼저 작성해 초기 표현 습관을 검수한다.
2. 나머지도 순차 작성하며 최종 언어만 먼저 읽고, 이어서 한국어와 근거표를 대조한다. 자연스러움, 가독성, 분야 적합성, 의미 일치, 확신의 정도를 각각 판단한다. 한 항목이 미달이면 평균으로 덮지 않는다.
3. 작성자는 자체 전수 재독을 기록한다. 별도 검수자는 실제 읽은 번들을 키별로 판정하고 수정본을 다시 읽는다. root는 실제 담당자를 유지한 채 현행 원고·검수 hash를 확인해 통합한다. 해시는 검수한 원고를 식별하는 용도다.
4. 누락·다른 언어 혼입·단락 수·문장과 짧은 행동의 중복·미완성 문구·검수 해시를 정적 검사한다. 자동 검사를 독해 검수로 표현하지 않는다.
5. 같은 카드의 다섯 분야와 서로 다른 카드로 구성한 세트를 비교한다. 점수가 문구를 고르는 규칙을 추가하지 않는다.

작성자 기록은 각 언어의 `author-review.json`, 별도 검수는 `review.json`에 남긴다. 검수는 에이전트 검수이며 인간·원어민 감수 인증을 뜻하지 않는다.

근거표의 `meaning_choice`에 남은 다른 분야·옛 형식 메모를 금전 156개 점검에서 23개, 건강 검수에서 매달린사람·완드7·펜타클7 정역 6개 정리했다. 한국어 본문·키워드·운 판단·기존 출처는 유지했다. [메모 교정 기록](brief-corrections.json)에 전후 내용과 실제 출처 열람 범위를 구분했고, root가 수정 메모 29개와 해당 한국어 전문을 다시 읽었다.

## 서버·클라이언트 계약

기준 dev는 `6ef287f5`다. 원격 dev를 fetch한 뒤 현 작업 기준과 일치함을 확인했다.

- 공개 `schema_version: 3`과 기존 필드명을 유지한다. `overall.flow`는 2~3개, 분야별 `text`는 1~3개의 단락을 수용한다. 새 카탈로그는 분야별 단락 수를 별도로 엄격하게 검사하고 기존 snapshot의 3/2 구간은 읽을 수 있게 한다.
- 새로운 세 언어 원고만 동시에 새 문구 버전으로 연결한다. 한 언어가 미완성이거나 검수본과 다르면 실행 자산을 갱신하지 않는다. 원고를 억지로 3/2 구간에 맞추거나 개행으로 숨겨 연결하지 않는다.
- 첫 방문 6세트의 ID·카드 조합·선택 알고리즘은 유지하고, 해당 카드의 새 원고로 세 언어 본문을 동기화한다.
- 기존 당일 snapshot과 광고 해금 상태를 임의로 삭제·교체하지 않는다. 문구 개편을 이유로 점수나 추첨 결과를 바꾸지 않는다.
- 현재 모바일은 `flow/text`를 목록으로 파싱하지만 화면에서는 KO/EN 공백, JA 빈 문자열로 연결한다. 모든 문장은 표시돼도 빈 줄이 사라진다. 모바일의 문단 표시 수정은 [별도 패치](mobile-paragraph-display.patch)로 준비했고 모바일 작업 폴더에는 적용하지 않았다. 기존 snapshot도 구간마다 문단이 나뉘는 표시 변화가 생기므로 패치에 그 영향을 명시했다.
- 모바일 건강 분야 제목은 아직 `활력 / Energy / 活力`이다. 별도 표시 패치에는 이를 `건강 / Health / 健康`으로 맞추는 변경도 포함한다. 기존 API 필드 `energy`는 유지한다. 서버 배포만으로 모바일 제목이나 빈 줄 표시는 바뀌지 않는다.

## 검증과 PR 준비

영어·일본어 각각 본문 780개와 짧은 문구 468개를 작성자와 별도 검수자가 읽었다. 최종 원고와 작성자·별도 검수 기록이 모두 일치하며 미해결 지적은 0개다. 세 언어 예시 4세트도 전문을 대조해 읽었다. 반복으로 검출된 평이한 행동·운 판단 2묶음은 전체 문맥과 한국어를 읽고 유지했으며 같은 본문 전체를 재사용한 항목은 없다. [정적 검사 결과](validation.json)와 [실제 독해 기록](review.json)을 구분한다.

다음 정적 검사가 통과했다.

- 한국어 검수 산출물, 현지화 원고·검수 기록, 예시 4세트의 현행 일치 검사
- 서버 자산 6개와 전체 대조 문서 6개의 재생성 일치 검사
- 세 언어 편집 자산 검사: 분야별 156개, 전체 780개씩, 누락·구조 오류 0개
- 변경 Python 파일 Ruff 검사, OpenAPI 계약·번들 일치 검사

최종 변경 범위에 DB 스키마·마이그레이션·환경변수 추가는 없다. 점수·점성술·카드 추첨·멱등성 서비스 코드는 유지했고 첫 방문 ID·카드·순서도 동일하다. 필요한 회귀 테스트는 CI에서 실행할 수 있도록 준비했다.

생성 후 별도 에이전트도 세 언어 원고와 실행 본문·짧은 문구를 대조했고 불일치는 없었다. 근거의 본문 해시 2,340개, manifest 자산 9개, 첫 방문 6세트의 90개 분야 본문을 확인했다. 이전 계산 규칙·legacy 자산 4개는 기준 커밋과 바이트가 같고 공개 단락 계약은 Python·OpenAPI 사이에 일치한다. 이 확인은 소스와 자산의 정적 검토다.

원고·연결 준비 단계에서 개인 AWS 계정·SSH·로컬 앱·Docker·DB·pytest·Flutter 테스트는 사용하지 않았다. 배포 검증도 로컬 서버 없이 개발 API와 해당 개발 Supabase의 전용 임시 계정을 사용한다. 다른 사용자의 결과·대화·전역 설정을 바꾸지 않고, 검증용 계정과 관련 데이터만 정리한다. 기존 개발 API 상태를 새 코드의 검증으로 세지 않는다. CI와 개발 배포 전후 API 검증 결과는 PR에 구분해 기록한다. 모바일 표시 검증은 별도 패치 적용 후 수행한다.

운세는 별도 worktree·브랜치에서 명시한 파일만 커밋한다. 병행 중인 대화 작업 폴더의 미커밋 변경이나 다른 브랜치 커밋을 가져오지 않는다. PR의 기준 브랜치는 `dev`다.

배포·복구 조건과 PR 본문 초안은 [PR 준비 원고](pr-draft.md)에 둔다. 새 단락을 읽지 못하는 기존 서버와 혼합 실행하거나 원본 이미지로 바로 롤백하지 않는다. [기존 문구 호환 빌드 패치](rollback-v6-reader-compat.patch)는 적용·배포하지 않은 준비물이다.

현재 [.github/workflows/deploy-dev.yml](../../../.github/workflows/deploy-dev.yml)은 대상이 정확히 1대인지 확인하고 중단 배포하며 공개 health의 전체 커밋 SHA를 확인한다. 이번 개발 배포는 이 경로를 사용한다. 여러 서버를 순차 교체하는 운영 배포는 이번 범위에 없고, 이후 호환 빌드 선배포 등의 조건을 별도로 충족해야 한다.

현재 새 영어 본문은 영국식 철자(favour, cancelled 등)를 일관되게 사용하며 공개 locale 키는 기존 `en`을 유지한다. 기존 색 이름·UI 번역은 이번 본문 철자 규칙에 맞추려고 임의로 교체하지 않는다.
